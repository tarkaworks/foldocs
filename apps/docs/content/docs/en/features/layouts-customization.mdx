# Layouts and customization

Foldocs ships four responsive layout compositions over the same semantic shell:

| Preset     | Composition                                                      |
| ---------- | ---------------------------------------------------------------- |
| `docs`     | Foldkit's direct fixed-header, sidebar, article, and TOC layout  |
| `notebook` | A contained navigation notebook beside an editorial canvas       |
| `flux`     | Compact navigation with the article and TOC on elevated surfaces |
| `glass`    | Translucent floating navigation and ambient color treatment      |

Select one in `foldocs.config.ts`. Search, i18n, root tabs, mobile navigation,
keyboard behavior, prerendering, and document markup stay identical between presets.

```ts
export default defineConfig({
  layout: { preset: "glass" },
  // ...
});
```

## Sidebar icons

Use an `icon` field in page frontmatter or a folder's `meta.json`. Foldocs ships
a tree-shaken set of Lucide defaults such as `book-open`, `file-text`, `package`,
`rocket`, `settings`, and `sparkles`.

```yaml
---
title: Deploy
icon: rocket
---
```

```json
{
  "title": "Manual installation",
  "icon": "package",
  "defaultOpen": false,
  "pages": ["pnpm", "npm"]
}
```

Projects can override a built-in name or define a new one with trusted SVG
markup in `site.icons`:

```ts
export default defineConfig({
  site: {
    title: "My docs",
    icons: {
      rocket: '<svg viewBox="0 0 24 24" aria-hidden="true">...</svg>',
    },
  },
});
```

## Own the customization source

Run the component-level customization command to copy stable project files instead
of editing package internals:

```sh
foldocs customize all
```

The command creates `src/foldocs/theme.css`, `layout.css`, and an optional typed
`mdx-components.ts`. CSS entry points are wired into `src/styles.css`
automatically, existing files are protected unless `--force` is supplied, and a
custom `--output` directory is supported.

```sh
foldocs customize theme
foldocs customize layout
foldocs customize mdx-components
```

## Landing-page composition

Select the built-in sections and override the hero copy without replacing the
runtime layout. The hero is required so every homepage keeps one primary heading;
every other section is optional.

```ts
landing: {
  sections: ["hero", "features", "ai", "cta"],
  headline: "Documentation that belongs to your product.",
  description: "Write Markdown. Ship a complete Foldkit site.",
  command: "pnpm create foldocs@latest my-docs",
  footer: {
    author: "Your team",
    authorUrl: "https://github.com/your-team",
    copyright: "Copyright 2026 Your Company",
    twitterUrl: "https://x.com/your-team",
  },
}
```

The footer configuration is shared by the landing page and every documentation
page, so attribution, source, copyright, and social links stay consistent.
